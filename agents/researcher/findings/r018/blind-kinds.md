# R-018 · Blind classification of 15 papers

Classified from the abstracts in `r018-input/abstracts.md` only. No paper text, no web, nothing else in the repo was read.

## Cases that were hard, and how you decided (write as you go)

#6 (holography). The abstract never says what the network is trained on. It says the derived metric is used "to train a real-time neural network-based phase generator", and the generator then produces holograms for new content at runtime. The metric itself is derived analytically (Rayleigh distribution), so it is not the reused work; the trained network is. A trained generator is valid as far as its inputs resemble whatever it was trained on, so B, but I am inferring the training set from the word "train". If someone wanted to be strict this could be "unclear" on the grounds that no training data is named.

#8 (MERF) was the closest call between A and B. The baked model is fitted by training on photographs of one scene, which looks like B (fitted to examples). But the photographs are all of one fixed problem instance, and what varies at runtime is the viewpoint, which the A definition lists explicitly among the things that may vary. The abstract frames the result as per-scene ("real-time rendering of large-scale scenes", "baking the parameterization used during training into a model") and says nothing about quality falling off for views unlike the training views, although for radiance fields in general that limit exists. I decided A: what the abstract says makes it go stale is the scene changing. I note the B pull (views far from the captured ones) as unstated by the abstract.

#18 (deep dynamic characters) is fitted to one person in one outfit, which is A-like, but at runtime it takes "an arbitrary 3D skeleton motion" and must generalize to new motions. A requires the reused work to stay valid "whatever else varies"; a learned motion-to-deformation model only stays valid for motions resembling the training video. So B. The per-character part is a second staleness condition (a different person or garment means retraining), noted in the table.

That decided a rule I then used for the rest: when the reused work is fitted to one subject but the runtime input is a pose, motion, expression or deformation state, it is B, because the B definition names exactly those ("sampled poses, motions or deformations") and validity depends on resemblance. When the runtime input is a view, a light or an edit to a fixed instance, it is A. This is what separates #8 (A, runtime input is a view) from #33 (B, runtime input includes expression and pose).

#33 (BakedAvatar) has both kinds in it. The baked textures carry view-dependent appearance (A-like, as in #8), but they also carry "expression-, pose-, and view-dependent appearances" learned from a monocular video, and the demonstrated uses are reenactment, expression editing and pose editing. The baking step itself is a deterministic conversion of the learned fields; what can go stale is the learned fields meeting an expression or pose the video did not cover, or a different person. Decided B.

#20, #56, #58 are all subject- or garment-specific learned models (A-like in being per-instance) driven by runtime motion or images. Same rule: B. #56 is the clearest case in the set, since the abstract describes the staleness directly: the regression is fine-tuned "to adapt the regression model to the new environment", i.e. it goes stale when lighting and appearance drift from the examples.

#40 (Penrose importance sampling) fits neither A nor B. The precomputed correction vectors are "obtained using relaxation" and applied to whatever importance density is given at runtime. They are not computed from a problem instance (the instance is the density, and it is the runtime input), and they are not fitted to example inputs. They belong to the method itself (the tiling and numbering). C: a problem-independent table that goes stale only if the method changes. One could argue the relaxation implicitly assumes something about the densities it will meet, but the abstract does not say so.

#41 (power budget). The abstract says the algorithm explores the power-error space and will "leverage optimal Pareto frontiers at runtime", which implies precomputed frontiers, but never says what they are computed from or depend on: the scene, the platform, sampled viewpoints, or measured power. Depending on the answer it could be A (per application and platform) or B (sampled settings and views). Marked unclear.

#48 (substructuring). The reduced models are built "given a volumetric mesh", per subdomain, so A: they go stale when the mesh or its partition changes, and "parts can be re-used" reinforces that the work is tied to part geometry. Reduced models also only cover deformations within their subspace, and if that subspace were built from sampled deformations that would be a B-type limit. The abstract does not say how the basis is built, so I kept A and noted the subspace limit.

#50 (subdivision quadtrees) is A: the quadtree is built per face of the base mesh "ahead of time". The abstract does not say whether animating control points invalidates it (it may depend only on face topology), so the staleness condition is stated as the base mesh changing, without saying which part of it.
